## 2. Tecnicas

- **fp16 no WebGPU**: transformers.js #1590 (aberto/reaberto 30/03/2026): encoder fp16 do Whisper degrada no EP WebGPU novo (v4); encoder fp32 + decoder fp16 resolve; v3.8.1 nao tinha o problema [T]. Isso confirma o seu "hibrido". Reportado com large-v3-turbo; para base nao verifiquei [?]. Parakeet tambem: int8 quebra no WebGPU, fp16 ok [T].
- **shader-f16**: Chrome 120+ expoe a feature [T]. Safari 26 liga WebGPU por padrao [T, Cinevva/Wikipedia]; shader-f16 no Safari [?] nao confirmado.
- **WebNN**: nao encontrei fonte; nao contar com ele [?].
- **Web Speech API on-device**: `SpeechRecognition.processLocally`, `available()`, `install()` existem; Chrome 139+ marca como suportado [T: MDN, caniuse]. Pacote de idioma ~60MB, um por idioma [T: blink-dev]. Edge 150 lista local: en-US, de, it, pt-PT, es-ES, ko [T: MS docs]; lista do Chrome [?] (testar com `available({langs, processLocally:true})`). Vantagem: CPU/GPU quase zero para o app, streaming real, gratis. Riscos: so Chromium, sem controle de modelo, pt-BR pode nao existir local, privacidade de menores se cair em modo remoto (so usar com processLocally=true).
- **LocalAgreement / whisper-streaming, cache de encoder/KV, TEN VAD, Silero v5/v6**: nao consegui fontes nesta rodada [?]. Conhecimento geral [E]: re-decodificar a cada 2 s custa N vezes mais; melhor emitir parcial so quando o VAD indica fala, usar janela deslizante curta e confirmar texto por concordancia de 2 passadas, e decodificar so o trecho novo apos pausa. Silero v5 ja e leve; ganho de trocar de VAD e pequeno.
- **Deteccao de idioma**: Parakeet v3 faz auto (25 europeus) [T]; Whisper tem deteccao embutida (custa 1 passo de decoder) [E]. Como o app ja sabe o idioma da pessoa, fixar o idioma evita erro e custo.

## 3. Recomendacao em camadas (a maioria e inferencia minha)

| Perfil                            | Escolha                                                                                                                    | Confianca                            |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Chrome/Edge recentes, qualquer PC | Tentar Web Speech `processLocally:true` se `available()` disser "available" para o idioma; senao Whisper                   | media (falta checar pt-BR no Chrome) |
| PC fraco (sem WebGPU ou iGPU)     | Whisper base q8 WASM, parciais menos frequentes (4-5 s ou so apos pausa do VAD), final com janela completa                 | media                                |
| Medio (WebGPU)                    | Whisper small (encoder fp32 / decoder q4-fp16), pt melhora muito sobre base                                                | media-baixa (sem RTF medido)         |
| Forte (GPU dedicada)              | large-v3-turbo q4 como opcao "qualidade", baixar sob demanda; ou Parakeet v3 fp16 (excelente WER, mas 2GB RAM e so chunks) | baixa-media                          |
| Celular                           | Whisper tiny/base so em final de frase; considerar Web Speech do SO                                                        | baixa                                |
| Safari                            | Whisper base WASM (ou WebGPU do Safari 26 apos teste); Web Speech do Safari nao e on-device garantido [?]                  | baixa                                |

Calor: o maior ganho provavel e reduzir re-decodificacoes (parcial so com fala, teto de frequencia adaptativo pela carga medida), nao trocar de modelo [E].

## Incertezas

Sem RTF/latencia em navegador por modelo; WER Whisper tiny/base/small em pt nao obtido de fonte; licenca exata do Moonshine base-es; Canary, Vosk, TEN VAD, LocalAgreement, WebNN nao pesquisados; lista de idiomas locais do Chrome; shader-f16 no Safari.
