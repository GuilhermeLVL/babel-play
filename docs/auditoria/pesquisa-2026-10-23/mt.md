## 3. Técnicas (todas [E] ou prática comum; ganho depende do app)

- Traduzir só a frase final (segmento estável), nunca parciais: corta 3-10x as chamadas em transcrição ao vivo.
- Cache por (par, texto normalizado) em memória + IndexedDB; legendas repetem muito (interjeições, falas curtas). Chave com hash; LRU de alguns milhares de entradas.
- Batching em lote de frases por requisição ao WASM; ganho maior no Bergamot (suporta lote nativo).
- Pivô via inglês só quando falta par direto (dobra latência e acumula erro; Firefox faz assim [V]). Para pt↔es considere direto se existir.
- Glossário: pós-substituição de termos do usuário/jogo de vocabulário, ou placeholders; Marian não aceita restrição lexical simples, então é tratamento externo.
- QE para escalar: heurísticas baratas (razão de comprimento, repetição de tokens, palavras não traduzidas, perplexidade do decodificador) antes de QE neural (CometKiwi/MetricX-QE são grandes demais para o cliente). Escalar só o pior ~5-10% [E]. Para menor idade, a nuvem só deve receber texto sem identificação, retenção zero.

Estimativa de uso por usuário [E]: 1 h/dia de vídeo ≈ 42 mil caracteres/h (≈ 120 palavras/min); 30 h/mês ≈ 1,3 M caracteres ≈ 0,32 M tokens de entrada.

- 100% na nuvem com m2m100: ~US$0,22/mês; Azure ~US$12,6; Google NMT ~US$25 (antes de franquias). Tudo em nuvem é inviável no grátis exceto m2m100.
- Escalar 5-10% (cache + só frases finais derrubam o volume): m2m100 ≈ US$0,01-0,02; Azure ≈ US$0,6-1,3.
- Grátis do Cloudflare (10k neurons/dia) comporta ~1 usuário pesado/dia no total: não é plano, é amortecedor.

## 5. Camadas recomendadas

| Dispositivo                          | Motor primário                                                                                                                 | Fallback                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| PC fraco (sem WebGPU, 4 GB)          | Bergamot tiny/base-memory, par direto, só frase final, cache                                                                   | Nuvem (m2m100) quando QE ruim, com teto diário |
| PC médio                             | Chrome/Edge: Translator API se disponível; senão Bergamot base                                                                 | Idem                                           |
| PC forte (WebGPU, 16 GB+)            | Mesmo que o médio; opcional (plano pago ou opt-in) LLM 1.7B-4B em WebGPU para "polir" a frase final ou exemplos de vocabulário | Bergamot                                       |
| Celular (Chrome Android, Safari iOS) | Bergamot tiny/base-memory com limite de modelo e bateria; sem Translator API (mobile não suportado) [V]                        | Nuvem com teto                                 |
| Safari desktop/iOS                   | Bergamot (WASM; vigiar memória do worker); sem API nativa                                                                      | Nuvem                                          |
| Firefox                              | Bergamot                                                                                                                       | Nuvem                                          |

Ordem de decisão: cache → API nativa (se `available`) → Bergamot → opus-mt só para pares sem Bergamot → nuvem (se QE baixa e cota do plano) .

## Lacunas

- COMET/BLEU de Bergamot por par en↔pt e en↔es (dashboard não carregou; ler comet-results.md do repo arquivado ou mozilla/translations).
- Tamanhos reais por par no R2 do projeto (medir).
- Latência por frase: medir no próprio app com 3 perfis de máquina.
- Licença do TranslateGemma (ToU vs Apache), do Hy-MT1.5 e termos de Google/Azure/DeepL para menores.
- Safari 26 e WebKit: confirmar nas notas de versão.
